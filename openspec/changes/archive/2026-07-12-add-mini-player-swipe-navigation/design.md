## Context

音乐列表在已选歌后显示固定底部迷你播放器，播放器复用 `usePlayerStore` 的播放、暂停与恢复状态。该 store 已公开 `playNext` 和 `playPrev`，但顺序模式在尾部停止、随机队列前后边界未提供用户确认的循环体验，页面也没有任何指针手势处理。

本变更只作用于迷你播放器，不新增独立播放器页或可见的上一曲/下一曲按钮。已确认交互为“左滑上一曲、右滑下一曲”、松手立即播放，以及顺序歌单首尾循环。

## Goals / Non-Goals

**Goals:**

- 为迷你播放器的非交互区域提供可预测的水平手势导航和跟手回弹反馈。
- 在顺序与随机导航的边界持续产生不同的可播放目标；单曲循环沿用已记录的基础模式进行手势导航。
- 保留播放/暂停按钮点击和页面竖向滚动的现有行为。
- 通过队列与页面测试覆盖切歌、循环、手势阈值和交互隔离。

**Non-Goals:**

- 不加入可见的上一曲/下一曲按钮、进度条拖动、音量控制或独立播放页。
- 不改变歌曲结束时已有的播放模式语义、歌单数据或持久化字段。
- 不为列表歌曲行增加滑动操作。

## Decisions

### 使用 Pointer Events 并以手势状态驱动视觉位移

迷你播放器根元素记录起始坐标；仅当水平位移大于竖向位移时更新 CSS 自定义位移，限制为一个小的最大偏移量。松手时，水平位移达到固定阈值才调用 `playPrev` 或 `playNext`；否则移除拖动状态让 CSS transition 回弹。Pointer Events 统一覆盖鼠标、触屏和触控笔，且不需要增加依赖。

替代方案是仅使用 Touch Events。它不能自然统一桌面指针，并需要额外处理被动事件；因此不采用。另一替代方案是让整张播放条可点击滑动，但会与播放/暂停按钮冲突；因此从按钮及其祖先元素开始的手势不参与识别。

### 阈值、方向与触发顺序

采用约 56px 的触发阈值，并要求水平移动量大于纵向移动量。向左调用上一曲，向右调用下一曲；触发后立即播放目标歌曲，随后播放条回到中立位置。触发期间禁用 transition，松手后恢复 transition。

固定像素阈值比完全按组件宽度计算更容易理解，并能在窄屏保持足够的误触保护。阈值以下不切歌，竖向移动只让页面保留正常滚动。

### 将导航循环规则收敛到播放队列服务

顺序队列的下一首与上一首 helpers 在首尾返回另一端的歌曲。随机队列的下一首在游标到末尾后建立新一轮队列，并从当前歌曲后的第一首开始；上一首在游标为零时回到当前队列末尾。`playNext` 与 `playPrev` 继续负责播放目标，保持页面不需要理解队列或模式规则。

替代方案是在页面中按可见搜索结果计算目标歌曲。这会把搜索 UI 状态与全局播放队列混在一起，也会和随机模式不一致，因此不采用。

## Risks / Trade-offs

- [纵向滚动时意外切歌] → 要求水平主导和最小水平阈值，且不在按钮区域开启手势。
- [快速连续滑动产生并发播放请求] → 在一次 pointer interaction 中只触发一次；每次切换由 store 的既有 `playSong` 路径收敛状态。
- [随机模式重建队列后重复当前歌曲] → 新队列将当前歌曲固定为游标位置，并选择其后一个可用歌曲；仅有一首歌时仍允许重播自身。
- [切歌动画影响可访问性] → 动画仅表示位移，不替代状态文字和按钮的可访问名称；状态更新仍由现有组件渲染。

## Migration Plan

1. 为队列循环与页面手势写出失败测试。
2. 修改队列 helpers 和 store 调用边界，使手势导航总能遵循确认的循环规则。
3. 为迷你播放器添加指针手势状态与最小样式反馈。
4. 运行页面测试、类型检查和生产构建；如需回滚，移除手势事件与位移样式即可，现有播放/暂停路径不受影响。
