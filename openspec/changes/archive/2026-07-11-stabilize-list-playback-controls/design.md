## Context

`SleepListPage` 当前将 `currentSongId` 对应歌曲抽成顶部特色卡片，并从普通列表中过滤掉。每次点击歌曲会改变 DOM 排列与内容高度，表现为页面跳动和自动置顶。页面已经使用 `usePlayerStore`，该 store 已支持 `shuffle`、`single`、`sequence` 三种模式及持久化、随机队列和歌曲结束处理，但列表仅暴露了“随机播放”快捷按钮。

## Goals / Non-Goals

**Goals:**

- 保持歌曲行的相对顺序和用户当前滚动位置，不因选歌改变列表结构。
- 用固定底部迷你播放器集中展示当前歌曲和播放/暂停状态。
- 在列表页清晰切换并展示随机、单曲循环与顺序播放模式。
- 复用现有音频引擎、状态和队列规则。

**Non-Goals:**

- 不新增独立播放器页面、进度拖动、上一曲/下一曲或播放队列管理 UI。
- 不改变已有的模式语义、歌单数据、离线缓存或持久化字段。
- 不调整搜索的匹配规则或重设用户的搜索词。

## Decisions

### 保留完整歌曲行列表，取消特色置顶卡片

列表直接基于 `filteredSongs` 渲染所有歌曲，歌曲行在原位通过视觉状态区分当前播放、当前暂停和非当前歌曲。点击行只更新播放器状态；不再根据当前歌曲构造 `featuredSong` 或过滤 `listSongs`。

替代方案是保留顶部卡片但不移除原行。该方案仍会在选歌时插入或替换顶部区域，造成页面高度变化与视觉跳动，因此不采用。

### 使用条件显示的固定底部迷你播放器

当 `currentSongId` 能解析为歌单歌曲时，页面底部固定显示迷你播放器；无当前歌曲时不显示占位播放器。播放器复用 `pause`、`resumeCurrent` 和 `playSong`，显示歌曲名与状态。列表容器增加底部内边距，覆盖播放器高度及设备安全区域。

替代方案是将播放器作为列表末尾的普通卡片。该方案滚动后不可见，无法提供持续控制能力，因此不采用。

### 通过循环按钮选择播放模式

模式控件读取 `playbackMode` 并按固定顺序 `shuffle → single → sequence → shuffle` 调用 `setPlaybackMode`。控件文字、图标和 `aria-label` 都反映当前模式和下一次操作结果。模式切换不重新开始当前歌曲；现有 store 在歌曲结束或切歌时应用新模式。

替代方案是弹出菜单。菜单更利于一次看到所有选项，但增加了一个额外浮层和一次点击；三个模式数量少，循环按钮更符合当前页面的简洁目标，因此不采用。

## Risks / Trade-offs

- [固定播放器遮挡最后歌曲] → 使用播放器实际高度和 `env(safe-area-inset-bottom)` 为列表预留空间，并在窄屏截图测试最后一行。
- [循环按钮模式不易辨认] → 始终显示当前模式文字与语义图标，提供说明性的可访问名称。
- [歌曲结束时模式行为回归] → 为三种模式及切换后的行为增加 store/页面测试，继续复用既有队列逻辑。
- [搜索期间当前歌曲不在结果中] → 迷你播放器从全量歌单解析当前歌曲，搜索只改变可见歌曲行而不影响底部控制。

## Migration Plan

1. 为列表顺序、底部播放控制和模式循环补充失败测试。
2. 移除顶部特色卡片和置顶过滤逻辑，渲染稳定的歌曲行列表。
3. 增加底部迷你播放器及安全区域样式，并接入既有播放器状态。
4. 替换“随机播放”快捷按钮为模式循环控件，使用现有 `setPlaybackMode`。
5. 运行单元测试、类型检查、生产构建和移动端浏览器验证。

## Open Questions

无。此变更采用点击循环而非模式菜单，底部播放器仅在已有当前歌曲时显示。
