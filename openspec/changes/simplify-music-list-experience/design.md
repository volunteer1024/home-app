## Context

当前项目以 TanStack Router 管理首页、发票页和 `sleep` 下的播放器、列表、设置子路由。音频目录、播放器状态和音频引擎已独立于页面存在，但列表页在选歌后会导航到 `/sleep/player`，并且页面仍保留首页、收藏和我的等未交付入口。

本次变更将当前版本收敛为音乐列表这一条用户路径。现有工作区含有用户未提交的页面样式与列表修改；实施时必须保留这些修改，除非它们与本变更直接冲突。

## Goals / Non-Goals

**Goals:**

- 将应用启动入口和唯一可见页面收敛为 `/sleep/list`。
- 在列表内完成歌曲选择、播放、暂停、继续、切歌与错误反馈。
- 删除或停用未交付页面的路由、UI、导航和相关静态展示内容。
- 更新 `PRD-v1.md` 与本变更技术/需求工件，使描述与可交付范围一致。
- 复用目录加载、播放器状态和音频引擎，避免改变歌曲资源格式或音频播放基础设施。

**Non-Goals:**

- 不重新设计歌曲视觉风格或引入新的音乐功能。
- 不实现发票、收藏、发现、我的或其他家庭工具功能。
- 不在本次变更中交付设置、离线缓存、定时停止、播放模式或歌词功能。
- 不迁移或改写歌曲目录与现有本地播放记录的数据结构，除非删除页面导致无引用代码。

## Decisions

### 以 `/sleep/list` 作为规范入口

保留现有列表路由并将根路径和旧页面链接统一导向它；不建立新的页面或复制列表组件。这样可以复用现有歌曲加载和布局，同时使旧书签不会落到失效页面。

替代方案是在根路径直接挂载列表组件。该方案会消除跳转，但会重复或改变现有路由约定，且需要处理更多路由生成与相对链接问题，因此不采用。

### 将播放控制移动到 `SleepListPage`

列表页直接调用 `usePlayerStore` 的 `playSong`、`pause` 和 `resumeCurrent`。歌曲行与当前歌曲展示根据 `currentSongId` 和 `status` 决定播放或暂停操作；选择非当前歌曲时调用 `playSong(songId, 0)`。操作完成后不再 `navigate('/sleep/player')`。

替代方案是保留隐藏播放器页或以弹层承载控制。隐藏页面仍引入不必要的路由与维护面；弹层会形成第二个界面层，违背单一列表页面的范围，因此不采用。

### 保留播放基础设施，删除页面级功能

`SleepRouteLayout` 继续负责歌单加载、播放器就绪和现有服务工作；仅保留列表实际使用的状态和组件。播放器页、设置页、首页和发票页及其专属路由、导航、文案、样式和无引用代码将在实施中删除。实现完成后通过路由生成命令更新 `src/routeTree.gen.ts`。

替代方案是仅隐藏导航。它会保留可直接访问的未交付页面，并继续维护无用代码，不符合范围收敛目标，因此不采用。

### 以文档先行锁定范围

先将 `PRD-v1.md` 改写为单页面产品需求，再由本设计和 OpenSpec 规格给出工程边界、测试场景与执行任务。文档中只保留已承诺的列表内播放能力，避免未确定功能成为隐性承诺。

## Risks / Trade-offs

- [旧书签和深链访问] → 将旧路由重定向到 `/sleep/list`，并在路由测试中覆盖这些路径。
- [删除页面后误删仍被列表使用的播放逻辑] → 先识别 `usePlayerStore`、目录加载、音频引擎的引用；删除后运行类型检查、构建和核心交互测试。
- [当前工作区存在未提交的页面修改] → 实施前逐文件审查差异，仅编辑与本变更直接相关的区域，不用重置或覆盖方式清理。
- [列表交互状态不清晰] → 为当前歌曲提供明确的播放/暂停图标、状态文本和可见错误反馈，并以交互测试验证。

## Migration Plan

1. 更新 PRD 和 OpenSpec 工件，确认唯一页面与验收范围。
2. 将根路径和所有旧页面路径导向 `/sleep/list`，并移除独立页面路由和对应 UI。
3. 修改列表交互，使当前歌曲可原地暂停/继续，选择新歌曲时原地切换。
4. 清理无引用组件、样式、文案及路由生成产物，保留播放服务与状态。
5. 执行类型检查、生产构建、路由访问和列表播放交互验证。

若发布后出现无法播放或无法进入列表的阻塞问题，可回滚本次变更提交，恢复原有页面路由与导航。

## Open Questions

无。本变更明确将尚未确定的功能全部移出当前版本范围；未来需要时以独立 OpenSpec 变更重新引入。
